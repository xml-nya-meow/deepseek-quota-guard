## 两列表格自动保存与内置日志

- 在“填写两列表格”选择一行后，修改名字或金额，**有效输入停顿 0.6 秒后自动保存**；“更新选中行”可立即提交，添加与移除行也直接保存。下方提示会说明是否成功，主表同步更新；金额无效、名字重复或外部文件冲突时拒绝覆盖。
- **撤销**退回上一次操作，最多保留最近 50 次已保存操作；当前还有未保存输入时，先撤回这段输入。**不保存本次修改**恢复到本次打开填写窗口时的内容并关闭，之前已经存在的保存不变。**取消**及右上角关闭只关闭窗口，保留已经保存的修改，不额外提交尚未保存的输入。
- 表格区域随窗口伸缩，底部“不保存本次修改 / 撤销 / 取消”独立排列。编辑只更新人员表，不启动管理或删除；保存后需重新读取费用。撤销或放弃会记录新的保存，不抹除账本、Key 绑定或历史处理记录。
- 主窗口、新建列表、两列表编辑、统计起点输入和日志窗口均可拖动调整大小。小窗口通过最小尺寸、固定按钮区和滚动区域保持操作可达，不额外限制放大；系统原生文件选择框、提示框保持 Windows 的行为。
- “打开诊断日志”进入程序内查看窗口，按需读取最近 **300 条、最多 256 KiB**，不持续积攒内存缓存。诊断保留 **14 天**，单文件约 **2 MB**、通常最多 **12 份**；当前活跃文件或无法确认是否活跃的文件优先保留，可能暂时超过份数上限。清理只针对本程序诊断文件，账本与删除处理记录不自动清理。

## 新建列表与强制删除

- “新建列表”替代“首次设置”，已有列表也可使用。弹窗选择“延续现有人员与个人额度”或“建立空白列表”，确认“创建新列表”后切换到新账本；取消不创建。原账本和历史记录保留，延续的个人额度不受新表默认值覆盖。
- 创建时即将所选默认额度写入正式人员表。空白名单以及延续名单中的空位使用 `-1` 或当前斩杀线；主列表、填写窗口和重新打开后的值保持一致。未填写姓名的行显示“待填写”，不绑定 Key、不核算费用、不触发自动删除。
- 两种新建方式都保留同一账户的 Key 绑定与未结清操作责任；新列表按选定起点重新读取费用，不复制旧费用作为新周期证据，也不会自动开启管理。
- “强制删除选中 Key”只处理本次选中目标。先登录、填写并选中平台 Key 名，程序独立读取完整 Key 列表核验身份，再确认一次准确目标；不要求先读取费用、达到个人或公共额度。`-1`、未知或过期费用也可使用此入口。
- 强制删除仍核验账户、名称、Tracking ID、目标互斥及未决操作，并记录 `intent=manual_force` 和当时真实额度、费用证据。它不会把旧费用更新成有效费用，不会解除结果未知操作，也不会删除账户最后一枚 Key。
- 强制删除的身份核验会使旧费用核验失效。dev10 中随后点击“启动全自动管理”，程序先使用当前会话重新读取 Key 列表与费用；完成后仍需确认本次管理范围。仅完成强制删除不会自行开启管理，读取失败或存在旧待核实操作也不会继续启动。
- 全自动管理保持原规则：`-1` 跳过、`0` 为零额度，正额度需要有效费用达到个人或公共上限；开启后无逐枚人工确认。

强制删除后启动管理的历史修复见 [dev10 开发记录](docs/开发记录-dev10-强制删除后启动管理与发布-2026-11-02.md)。自动保存与日志见 [dev9 开发记录](docs/开发记录-dev9-自动保存与内置日志-2026-11-02.md)，更早的 [dev8](docs/开发记录-dev8-默认额度持久化与启动诊断-2026-11-02.md) 和 [dev7](docs/开发记录-dev7-新建列表与强制删除-2026-11-02.md) 记录保留原样；历史验收不替代当前版本的新一轮验证。

## 斩杀线与外观

- **斩杀线是未来新表的默认个人额度**，最小 `0`，支持最多 18 位小数。选择“新表默认填：-1（跳过管理）”或“斩杀线”，点击“保存新表默认”；“新建列表”中也可选择。初始选择仍为 `-1`。
- 例如斩杀线设为 `0.1`，新表选择斩杀线，就为新人员预填 `0.1` 元；填写并保存后，仍按累计费用达到个人或公共额度的原规则处理。修改默认值不会改写已有人员额度，也不会成为额外的全局限额。
- 新列表生成时即保存所选金额，未填写姓名的行也保留该金额；取消后续编辑只放弃尚未保存的编辑，不把已生成的 `0` 或正数改回 `-1`。已有命名人员额度不变。导出的 Excel 模板按当前人数预填所选金额（尚未设置时 14 行）；**外部导入仍严格校验**，空名且非负额度的行须补姓名、改为 `-1` 或删除后再导入。
- **全自动管理中 `-1` 始终跳过；`0` 是零额度触发，不是跳过。** 用户明确选中的 `-1` 可强制删除。所有删除仍经过身份、目标和操作状态核验。
- “外观”按钮依次切换跟随系统、浅色、深色，默认跟随系统并记住选择。跟随模式每 5 秒检查 Windows 应用主题；不改系统设置。原生文件选择框和消息框由 Windows 绘制。

斩杀线与外观的历史改动及验收见 [dev6 开发记录](docs/开发记录-dev6-斩杀线与外观-2026-11-01.md)。

## 关于实现原理的简单解释

程序分为浏览器会话、平台采集和本地账本三个部分，网页操作与 HTTP 请求配合完成工作：

这是独立 Windows 程序，没有 DSH 插件、网关、虚拟令牌或 `user_id` 注入，模型调用不经过本软件。各模块和函数关系见[实现说明](docs/implementation-explained.md)。dev14 先从人员表确定受管范围，再把对应 Tracking ID 以重复的 `api_key_tracking_id` 参数发送到费用接口；授权从 Key 列表请求取得，不为此打开会触发默认全账户费用请求的用量页。删除与身份核验仍独立检查完整 Key 列表。

1. **登录与授权。** 程序打开自己的临时独立浏览器，由你登录 DeepSeek 开放平台。它观察这个会话发往允许接口的请求，取得对应接口需要的授权头，只保留在浏览器工作进程内存中。程序不读取日常浏览器的 Cookie，也不要求把完整模型 API Key 填进人员表；重新登录会更换会话及授权材料。
2. **读取 Key 与费用。** 普通采集流程从 API keys 页的页面结构（DOM）读取 Key 名称和 Tracking ID。费用则通过控制台费用接口的 HTTP GET 获取：按当前账本起点和本次 UTC+8 截止日期动态生成参数，将包含结束日的日期范围转换为“起点零时至结束日次日零时”的区间，并传入 `tz=28800`。程序不会写死某个历史日期，也不依赖操作网页日历读取账单。删除模块另外使用管理 HTTP Key 列表校验目标映射，不能把普通采集和删除模块都描述为纯 HTTP 读列表。
3. **本地核算与记账。** 同一费用响应中的模型系列与函数系列，按 Tracking ID 汇总每个有效桶的实际 `cost`；不以 token 数或工具次数另乘单价，不再次加入顶层合计。GUI 仍核对本地人员表、绑定、统计期间和累计金额，再应用到 SQLite 账本。费用是周期累计值，用核验后的累计替换对应记录，不把每次读取值重复相加；费用、快照和相关事件通过事务保存。HTTP 成功和解析成功并不等于账本已经接受；账本提交后导出文件或刷新界面失败，也不等于费用从未写入。缺失费用保留未知或历史下界，不按零元补齐。
4. **正式删除。** 达额的全自动流程或用户明确确认的强制删除，共用目标与操作核验。准备完成后，只向管理接口提交一次删除 POST；随后通过管理 HTTP 列表和重新加载后的网页列表复核原目标缺席，并核对仍存活的已知 Key。结果不明时保留待核实记录，不连续重发，也不回退到点击网页删除图标。
5. **停止自动管理后的读取。** “停止管理”停止后续自动操作；普通“立即读取费用”仍可能取得占用、写入 Key 绑定、应用费用快照、保存事件和导出日志。它对平台不发删除请求，但不是对本地账本的只读诊断。不要在真实账本上反复修改统计起点来排障；单独验证 HTTP/解析或账本应用时，应使用相应诊断范围或隔离账本。

程序依赖独立浏览器成功登录、页面导航与允许请求出现，也依赖页面列表结构和控制台内部接口。这些接口不是 DeepSeek 承诺稳定的公开管理 API；网页改版、授权字段变化或响应结构改变都可能需要适配。当前“先进入 API keys，再点页面空白处”的建议来自成功操作反馈，点击空白处是否必需及其具体作用尚未验证。保留浏览器并不意味着已有授权一定可用，接口返回成功也不能替代身份、费用和结果核验。

## 工作方式

- 人员表只填写平台 Key 名和个人额度，不填写真实 API Key。公共人均额度固定为本期总预算除以人数后向下取整。
- 全自动管理在费用、账户连续性、人员名和 Tracking ID 核验通过后，达到个人额度或公共人均额度都会触发撤销。不能核实的数据保留为未知或历史已知下界；强制入口的依据是用户对准确目标的明确选择，不伪造达额证据。
- 平台账单可能延迟；页面改版、身份变化、日期范围或字段校验失败时停止相关操作。结果未知的删除不会自动重试，需要人工核实。
- 登录使用独立浏览器上下文，不读取日常浏览器的 Cookie；关闭程序后不保留登录状态。
- 费用通过控制台 HTTP 接口读取，日期直接转换为请求参数，不再操作日历。受管费用采集从本程序独立浏览器的 Key 列表请求取得会话授权，不为此打开会触发默认全账户查询的用量页；授权只保留在工作进程内存。自动撤销使用控制台 HTTP 候选适配器，依据平台公开前端代码核对字段；页面列表仍用于身份和结果的独立核实。
- 点击“启动全自动管理”时确认本次管理范围与不可恢复的撤销行为，开启后由程序自动完成后续核验、平台删除确认和结果核查；无需逐枚人工审批，重启或停止后不会自行恢复管理。
- “强制删除选中 Key”独立读取完整平台列表并核验所选目标，由程序完成删除和核实，不启动周期轮询。它与全自动管理共用提交执行器、身份、审计和未决操作保护，但不要求有效费用或达到额度；不需要再到网页点击删除。
- 自动管理间隔可在主界面修改并保存，默认 10 秒，允许 1–3600 秒整数。每轮完成后等待所设秒数再读，不重叠请求；修改间隔不启动管理，也不延长费用证据的五分钟有效期。
- “检查删除准备（只读）”检查当前选中已绑定目标的真实管理授权与目标映射，不要求达额，不发送删除、不记为撤销成功。预检和实际删除共用准备代码；实际删除仍重新核验。
- 撤销准备在首次 Key 列表加载前观察本程序会话的允许请求，授权只保留在内存。准备失败会显示固定原因码，区分未观察到请求、授权缺失或格式拒绝、弹窗待处理和目标核验失败；诊断仅记录允许的头名称和有限的拒绝类别，不输出头值、凭据或请求原文。依据已观察的官方前端，仅设备型号头允许保留空字符串，其他字段的要求不变。
- 自动撤销要求目标本人具有本次有效费用，历史下界只供查看；明确零额度仍可独立判断。读取跨日、超过五分钟或配置改变后须重新核验。发送前使用短期一次性许可，由程序自动校验和签发；身份、接口结构或结果无法确认时停止。HTTP 不重试、不跟随重定向、不转用页面删除；只有独立核实原目标已不存在才记录成功。
- 本轮明确失败在提交准备阶段时显示“准备失败，未提交”；进入可能提交阶段后，超时和异常仍保留“结果待核实”。旧未知操作即使只读观察到 Key 仍存在，也不会自动解锁或转为未提交；“待处理”不代表平台已冻结 Key。
- 处理记录关联操作编号、当时规则及费用快照；强制入口另记 `intent=manual_force`，后续状态与跨账本继承保留该标记。待核实目标即使被移出人员表，也保留只读核实入口；“仍存在”与“授权前取消”分别记录。
- 支持修改统计起点、保存两列 Excel 模板和直接导入 `.xlsx`。更换日期建立新账本并保留原记录；导入先显示人数与零额度人数，确认后替换当前人员表。
- “登录 / 重新登录”每次重建会话。旧的未完成采集会失效，已提交的停用结果先记账；不会因重新登录而自动恢复管理。
- 自动关闭已识别的可选“绑定邮箱”提醒；不会填写邮箱、发送验证码或关闭登录验证和删除确认。提醒中已有填写内容时暂停，由用户处理。
- 操作按钮显示待登录、已核验、处理中及已完成状态；全自动管理显示“全自动管理：已开启”。当前阶段与耗时持续显示，普通读取失败不阻塞整个窗口。
- “中断当前操作”停止后续任务并清理本程序的独立浏览器进程，会话需重新登录；已提交的撤销仍保留待核实记录，账本不会清空。浏览器任务另设整体超时。
- “打开诊断日志”在程序内显示近期步骤、耗时、进程、结构摘要、原因码及结果类别，可手动刷新或打开文件夹。按 14 天及约 2 MB × 12 份限制清理，保护活跃文件；不保存凭证、请求头值或原始响应正文，账本审计不受此清理影响。
- 人员名、Tracking ID、费用及处理记录保存在本机数据目录中。不要公开数据目录、原始账单或登录截图；反馈问题时仅提供已检查并脱敏的必要诊断日志片段。

完整操作说明见 [使用说明](使用说明.md)。官方 CSV/ZIP 导出目前仅用于检查结构和日期，不能据此自动推算逐 Key 的实际扣费。

人员表模板：[下载人员额度模板](templates/人员额度模板.xlsx)。网页预览时可用 GitHub 文件页的下载按钮，也可在应用中点击“保存 Excel 模板”。只要求规定的两列表头和有效数据，不限制字体、颜色、数值显示样式或工作表名称。公式不会执行；读取已有计算结果，缺少结果时提示先重算并保存。

## 从源码运行

GitHub 仓库提供源码、测试、空白模板与说明，**不包含 EXE、真实账本或登录资料**。本次同步 dev16 的当前源码修复，不创建二进制 Release。需要运行时可按下方步骤从源码启动，或自行构建便携目录；本地已经生成的试用包不会因源码修改自动升级。

需要 Windows x64 和 Python 3.13.17。以下命令均在仓库根目录执行，使用 PowerShell：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path $PWD 'browser-runtime'
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe main.py --data-dir .\data
```

先用 `py -3.13 --version` 确认补丁版本为 3.13.17。构建也支持已有的 Python 3.12.14 环境，实际版本记录在 `BUILD-INFO.json` 中。安装依赖和浏览器会联网下载软件；首次运行应用不会自动调用付费模型接口。平台登录和费用读取需要网络。

`requirements.txt` 列出直接依赖，`requirements.lock` 固定当前 Windows 构建环境中的直接与传递依赖。请使用干净虚拟环境，更新依赖时同时更新锁文件和第三方声明。

- 费用延迟、在途请求和并发调用可能导致超额。

- dev16 已修复首次获取部分目标后失败、回滚又失败时丢失清理对象的极端路径；异常时保持停止，由原线程在正常关闭窗口时重试清理。冲突引用关闭失败也保留清理责任，不释放其他实例所有权。合成注入已验证；没有证据将该极端路径认定为所有历史读取失败的根因。
- 程序的强制删除和全自动撤销都须有另一存活 Key 核验账户连续性；本程序不删除最后一个 Key，如需删除须由用户自行在官网处理。重启核实须有存活的已绑定 Key。
- 同一账户应由一台设备管理。新版在 Windows 本机为已核验的完整 Key 列表及账本待核实目标取得互斥，覆盖不同数据目录，避免两个实例互删彼此的账户证明 Key。停止管理或重新登录不提前释放，完成浏览器清理并关闭窗口后释放；平台处理前由退出见证确认保留互斥引用，父进程意外退出时也等待旧进程树结束再释放引用。它不是稳定账户标识，不保护其他设备、未采用该互斥协议的旧版本或管理员在控制台的外部操作，也不保证父进程与见证同时被强杀时的完整退出交接。
- 设置和统计库完整、仅人员表缺失或损坏时，可进入受限恢复模式：查看待核实操作、登录原账户、核实原目标，并导入有效人员表。恢复不清零账本、不放宽账户连续性证明，也不发新撤销许可。
- 正常关闭或中断会清理本次临时目录。新会话另有短生命周期的退出见证进程：确认本次浏览器进程树全部退出后记录证明；下次建立会话只回收本程序专用根下、所有权与退出证明完整的残留目录。旧版无标记目录、证明不全、进程存活或身份不明、路径含重解析点的目录会保留。合成进程强杀与保留边界已纳入离线回归，冻结程序与干净 Windows 的结果须单独记录；不承诺强杀后立即消除全部磁盘痕迹。不要把运行后的便携目录直接作为公开发布包。

## 实际改动

### 费用应用与恢复

- 保留 `DataStore.apply_snapshot()` 的人员结果列表兼容接口；GUI 使用新增 `apply_snapshot_result()`，明确本次观察来源、实际有效快照、应用结果、持久化状态、导出状态和绑定覆盖计数。
- 费用无绑定、费用与绑定无交集、累计下降、来源冲突、期间不符和截止回退，各有受控原因码。拒绝时保留原费用、绑定与历史；不按姓名替换 Tracking ID，不将未知费用填零。
- GUI 区分 worker 失败和返回后的本地应用失败。已核验身份后的明确本地拒绝保留浏览器会话，但停止自动处理、清除费用有效性和删除许可。真正授权失效仍失效会话；未知类型或未知提交结果仍保守停止。
- 提交后导出、上下文读取或界面刷新失败，明确标记已经持久化，并进入“保存处理记录”的本地恢复队列。恢复只重新导出、只读评估和刷新，不重复应用费用、不重新记录业务触发、不产生新的平台观察时间。
- 新增 `read_evaluation()`、`current_snapshot_id()` 只读查询，支持恢复和最终有效性核验。
- 保留费用、快照、额度触发事件同一 SQLite 事务。事务异常不能仅靠缺少成功日志声称没有写入；不明确的持久化结果显示待核实。

### 旧快照与观察时间

- 区分新快照、重复观察当前最新来源，以及重新收到更旧来源。
- `S1 → S2 → 旧 S1` 保留 S2 金额，但旧 S1 不能使 S2 重新取得“刚核验过”的动作资格，也不由旧来源产生新的触发记录。
- 真正重新观察到当前最新 S2 可以更新观察时间，保持费用未变化时的正常周期管理。
- GUI 只在导出、只读刷新、上下文与来源核验完成后发布费用有效状态；最终资格还需与数据库当前快照来源一致。
- 无费用响应保留独立的身份核验路径，沿用零额度和 `-1` 跳过规则；正额度未知费用仍不授权自动删除。

### 诊断与构建识别

- 每次采集使用同一个 `operation_id` 关联 GUI、浏览器控制器、worker 和本地应用日志。
- 增加应用阶段、受控原因、保存/导出状态、7 项绑定与费用覆盖计数。费用来源只记录符合格式的 SHA-256，不记录原始账单、姓名、完整 Tracking ID、Cookie、Authorization 或完整 Key。
- 启动日志增加版本、基线提交、运行代码摘要和诊断格式版本。代码摘要包含未提交的运行代码变化，避免把基线提交误当成完整成品身份。
- 便携构建将识别信息写入 `BUILD-INFO.json`，启动时有长度和格式检查；不可用时标记未知，不读取外部凭证。
- 继承原有日志大小、数量、保留期与预览上限，没有加入远程日志服务。

### 文档与许可证

- README 新增“关于实现原理的简单解释”，解释独立浏览器会话、HTTP 费用请求、普通采集的 DOM 列表、删除模块 HTTP 列表与单次 POST、本地账本应用及交叉核验。
- 明确“停止自动管理后点击读取费用”仍可能写入绑定、快照和事件，并非本地只读。
- 项目自身从 dev11 起改为 Apache License 2.0；`LICENSE` 使用 Apache 官方原文，`NOTICE` 保留 `Copyright (c) 2026 xml-nya-meow`。

## 改动理由

用户提供的 4 份日志共 326 条记录，显示 6 次从 10.29 起的费用读取均已完成 HTTP 请求和解析，之后 GUI 报 `GuardError`。原通用失败处理将 worker 和 GUI 账本应用异常混在一起，会使本地拒绝表现为读取失败、登录待核验。

第七轮审查建议先区分费用是否取得、是否被账本接受、是否持久化、导出/刷新是否完成。本轮沿用已有事务、累计替换、部分覆盖、历史下界、零额度和自动动作门禁，只补足结果与恢复语义。

审查还提出旧快照重放和观察时间错配的静态风险。本轮用合成数据补充验证和防护；它不能被称为此前六次真实失败的已确认根因，也没有真实误删证据。

用户补充：当时没有保留窗口，也没有具体错误文字，只记得按钮提示获取失败。因此本轮不以缺失的状态栏信息猜定真实分支。

用户另提出缓存或残余进程的可能性。只读审查确认：费用 reader 缓存会话授权，不保存复用的费用响应；每轮重新发送指定区间 GET。登录会清理并重建浏览器，原日志中 worker 重建后仍失败。进程与任务已具有会话编号、任务编号和代次检查。因此本轮没有增加“每个按钮都强杀进程”，避免截断已提交但尚待核实的操作；保留现有中断、超时和清理机制。

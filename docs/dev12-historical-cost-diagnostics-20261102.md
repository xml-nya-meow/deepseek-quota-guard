# dev12：历史费用诊断、日期假设验证与结果说明

日期：2026-11-02；状态：本地候选，真实历史费用问题尚未验收。

## 实际改动

- 平台业务拒绝不再一概引导重新登录。HTTP 401/403 的授权失败仍独立处理；非零业务码的具体成因保持未知，不自动缩短统计起点或重试。
- 采集诊断补充请求时区和天数、分桶范围、固定业务消息字段的存在/类型/限长信息；不保存其正文、任意字段名、HTTP 头值或原始账单。
- 费用解析后统计费用 Tracking ID 与当前平台列表的交集，与现有本地账本交集配合定位问题。只记录数量和固定来源枚举，不记录标识或名称。完整 UUID 的大小写等价数量仅作诊断，不改实际费用键、绑定或授权。
- 主窗口增加可随窗口缩放换行的“费用核验”摘要，显示期间、空明细/平台拒绝/未匹配/已应用，以及当前受管费用覆盖。无明细明确为未知，不把今天的空查询呈现为消费核算成功。
- 采集派发时固定本地上下文；返回后在写入绑定或费用之前比较账本对象、期间、账户、人数、预算、人员表摘要和请求起点。空明细也执行相同保护，避免旧期间的空结果取得当前期间身份核验资格。正常日期切换原有会话代次保护继续保留。
- 保留原业务规则：未知费用不补零，不按姓名合并 Key，不放宽 `NO_BOUND_COST_MATCH`，不自动改绑，不将大小写诊断直接用于删除。零额度、负一跳过及强制删除原规则不变。

## 改动理由

最新 dev11 的 4 份诊断共 368 条记录，关联 7 次读取：09-29 起点四次业务拒绝；10-29 起点一次成功返回费用但本地零匹配；11-02 起点两次空明细。HTTP 成功、取得费用、账本应用和允许自动处理是不同阶段，不能用“只有当天成功”概括为平台日期规则。

只读检查用户本地的三个已绑定账本：起点分别为 09-29、11-02、10-29，账户标记与绑定集合相同；两个绑定均为 active，没有退休绑定。所有费用与快照表均为空，数据库检查前后摘要一致。因此本轮未发现日期进入账户身份的证据，也不能从“全部绑定 2、受管 1”推断另一枚已退休。

对外部分析逐项核对后确认：费用解析明确取 `api_key.tracking_id`；页面根据 Tracking ID 表头定位并检查完整 UUID；空明细前已核验身份；独立浏览器不持久化复用日常浏览器 Cookie。模型字段误作 ID、空明细跳过身份、固定列号错位等猜测均不符合当前实现。UUID 大小写可能影响严格集合匹配，但尚无真实证据；本轮仅增加可定位该情况的计数。

本轮以官方公开文档为优先依据：[查询余额](https://api-docs.deepseek.com/zh-cn/api/get-user-balance/) 是账号级余额；[限速与隔离](https://api-docs.deepseek.com/zh-cn/quick_start/rate_limit/) 没有承诺按用户的独立金额限额；[Search/Fetch](https://api-docs.deepseek.com/zh-cn/guides/search/) 用于网页搜索与抓取。本轮未找到公开支持的历史逐 Key 账单或 Key 撤销接口，也未找到本次控制台费用接口固定 30 天限制的官方说明。社区关于 UI 跨度的观测不能直接解释本次业务码，不据此改成 30 天分块。

网关仅保留为备选。它能控制未来经过网关的流量，但不会自动补回已发生的原生 Key 直连历史；本轮没有替换原生 Key 管理路线。

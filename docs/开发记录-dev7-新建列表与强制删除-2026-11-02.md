# dev7：新建列表与强制删除（2026-11-02）

版本：`0.1.0rc6.dev7`，本地候选试构建。保留此前 dev6 未提交改动、旧便携包及真实账本。本轮不登录真实账户、不调用付费 API、不撤销真实 Key、不提交或推送。

## 一、实际改动

- “首次设置”改为“新建列表”，已有列表也能使用。对话框选择延续现有姓名和个人额度，或建立空白列表；确认创建才建立独立账本，取消不创建。人数、预算和统计起点可单独设置；默认沿用已有配置。
- 延续模式保留原人员额度，新增空行使用 `-1`；空白模式在填写窗口按当前 `-1` / 斩杀线设置预填草稿。未填写姓名的非负额度仍需在保存时明确转成 `-1`。旧列表完整保留，新列表费用重新读取。
- 两种新列表都保留同账户 Key 绑定、已退休身份和未结清操作责任。使用暂存目录、源表指纹校验和原子发布；创建或切换失败不覆盖旧列表。零预算确认返回后再次检查原表与会话状态。
- 独立按钮改为“强制删除选中 Key”。先独立读取完整平台 Key 列表并核验当前选中名字与 Tracking ID，再确认本次准确目标；不要求费用读取成功、费用新鲜、达到个人/公共额度，`-1` 也可明确强制删除。
- 新增只读 `read_keys` 浏览器动作与严格进程协议，只传名称、Tracking ID 和账户标识；不返回费用、不刷新费用证据时间、不发删除许可。仅所选名称必须唯一，无关 Key 重名不阻断唯一目标；完整列表的重复 ID 仍拒绝。
- 强制删除与全自动管理共用提交、账户与目标核验、目标互斥、单次许可、结果核实和审计。新操作记录 `intent=manual_force`，后续状态及跨账本继承保留；实际额度、费用和状态原样记录，不伪造“达到额度”。
- 全自动管理的额度规则不变：`-1` 跳过，`0` 可触发，正额度依赖本次有效费用达到个人或公共阈值。强制删除不会启动周期轮询，也不会恢复旧费用的自动授权资格。
- 更新 README、使用说明和验证计划；保留斩杀线、外观和默认 10 秒可调间隔等已有改动。

## 二、改动理由

旧独立删除入口仍要求达到额度，不能满足用户指定任意目标强制删除的要求。此次拆开“是否因额度触发”与“是否为正确账户、正确目标、可确认的一次操作”：只有全自动管理需要额度触发，单次强制删除依据用户对准确目标的明确选择。

新建列表需要支持持续使用，同时不能用空白名单或新周期清掉已有账目和未知操作责任。旧账本与完整历史保留，新账本继承必要身份和操作状态，重新核对费用。

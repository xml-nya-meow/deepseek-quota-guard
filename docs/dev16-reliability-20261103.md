# dev16 修复与验证记录（2026-11-03）

版本：`0.1.0rc6.dev16`，候选预发布。基于公开 dev15 源码建立独立开发目录，保留此前未提交源码、旧包及真实账本。本轮只做离线验证和公开资料研究，不访问真实账户、不调用付费模型、不删除真实 Key。

## 一、实际改动

1. **首次申请目标保护的恢复。** `TargetLock()` 先建立可保留的清理对象，再由 GUI 保存该对象并调用 `update()` 申请完整目标集合。中途失败且回滚释放也失败时，窗口仍持有剩余句柄，保持停止并允许正常退出时重试清理。兼容旧式带目标构造调用：异常携带仅在本进程使用的 `cleanup_owner`，不得经 IPC 传输。
2. **冲突引用关闭失败的恢复。** Windows 返回“对象已存在”后，本次获得的只是引用，没有该互斥对象的所有权。若 `CloseHandle` 失败，保存为 `owned=False` 的待清理句柄，后续只重试关闭；不调用 `ReleaseMutex` 释放竞争实例的所有权。失败尝试不会获得有效目标覆盖。
3. **删除准备的精确诊断。** HTTP 列表读取区分授权拒绝、重定向、状态、响应类型/大小、JSON、业务结构、目标字段及完整身份列表不一致。固定原因码贯穿只读预检、删除准备与进程通信；字段诊断仅保存允许的字段名称、存在性、类型、封顶长度及行序号，不保存响应值、管理 Bearer 或 Key。
4. **HTTP 重复身份检查。** UUID 大小写不同但内容相同的重复 Tracking ID 也拒绝，与网页完整列表的重复检查保持一致。
5. **补齐跨周期离线验收。** 用真实 GUI、真实临时账本及实际 Tk 定时回调，配合合成浏览器结果验证正额度后续周期跨线、费用缺失和停止操作。
6. **公开说明。** README 独立列出替代网关方案、平台真实删除无恢复渠道、学习用途与中小规模审慎评估、个人维护能力限制。网关只作为资料参考，未将本项目改造成网关，也未复制或运行第三方服务代码。

## 二、改动理由

初次获取多个目标的原代码直接在构造函数里执行申请。若后续目标申请失败，已经取得的句柄又无法释放，构造函数会抛出异常，GUI 尚未完成赋值，因而没有可重试清理的所有者。这是已合成复现的极端资源恢复缺口，不等于每次普通竞争都会泄漏句柄，也不能用来解释所有历史读取失败。

检查同一段生命周期时，发现“打开了已有互斥对象但关闭引用失败”的相邻缺口。修复重点是保存清理责任和区分引用/所有权，保持完整目标集合互斥；没有自动接管旧实例、缩小保护范围、强杀浏览器或伪造会话就绪。

旧 `KEY_TARGET_READ_FAILED` 将多个校验分支合并，现有历史日志无法还原具体字段。本版补充可公开反馈的精确诊断，**没有凭猜测接受任意时间单位、放宽脱敏标识格式或跳过完整列表检查**。明确未发送的准备失败与许可发出后的结果未知仍严格区分；结果未知不自动重发。

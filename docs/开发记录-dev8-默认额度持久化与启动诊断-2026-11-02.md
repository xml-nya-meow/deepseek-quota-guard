# dev8：默认额度持久化与启动诊断（2026-11-02）

版本：`0.1.0rc6.dev8`，本地候选版。保留已有未提交改动、旧包及真实账本。本轮没有真实账户访问、付费调用、真实 Key 撤销、提交或推送。

## 一、实际改动

- 新建列表时即把所选 `-1` 或斩杀线金额写入正式人员表，主列表与填写窗口一致。关闭填写窗口、取消后续编辑或重新打开账本，都不再把已生成的 `0` 改回 `-1`。
- 无姓名行可在内部人员表中保留有效金额，状态为“待填写姓名 · 不参与管理”。这些行不能绑定 Key、不能取得费用或触发额度事件；公共额度为零时也不参与。填写有效姓名并保存后才按正常规则参与管理。
- 延续列表保留已命名人员的原额度，空位使用本次默认值；仅修改统计起点的旧后继流程保留现有占位金额。默认值保存不批量改写已有名单。外部 Excel 导入仍严格拒绝空名非负金额，公式、无效金额和精度限制未放宽。
- 登录前增加自有 `127.0.0.1` 临时监听口的有界通信检查，`connect` 与 `accept` 共用 2 秒预算，不调用存在阻塞风险的 `socketpair()`。失败即关闭本次套接字并返回固定错误，不进入 Playwright 初始化，不修改系统网络。
- 启动阶段区分“检查本机浏览器通信”“初始化浏览器驱动”“启动独立浏览器”。登录失败明确弹窗，回调先释放忙碌状态，再显示错误，登录仍可重试。2 秒仅指本机通信检查，不是整个登录期限。
- 强制删除时未选中已命名人员、或尚未登录，会明确提示没有派发删除，不再只把说明放在可能不可见的底部。修正主界面仍写“单次删除仅处理已达额 Key”的过时说明。
- 强制删除和全自动管理的身份、额度及审计边界保留；此轮没有改为绕过账户、目标或未知结果保护。

## 二、改动理由

用户截图中，右侧草稿显示 `0`，主表却显示 `-1`。dev7 仅在编辑草稿中应用默认值，正式表先保存 `-1`，与“新表默认填斩杀线”的预期不符。dev8 让默认值真实持久化，并以空名行的未分配状态阻止误管理。

对“点击强制删除后登录卡住”的本地日志核对发现：该次强制按钮立即返回，没有派发 `read_keys` 或 `revoke`；随后三次登录均停在“正在重建登录会话”，用户中断/关闭均有完成记录。因此不能把这次故障描述为已提交删除死锁。

独立、无账户的 5 秒堆栈采样复现了 Playwright 初始化阻塞：`sync_playwright → asyncio.new_event_loop → proactor._make_self_pipe → socket._fallback_socketpair → accept`。Python 和 .NET 对本机回环的独立连接都返回 `10051`。只读路由查询在当前执行环境中未看到 IPv4 `127.*` 路由；这不证明具体由哪项系统配置或软件造成。本轮没有擅自修改系统网络、防火墙、代理或路由。

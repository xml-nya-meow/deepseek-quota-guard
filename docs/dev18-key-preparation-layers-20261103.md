# dev18：完整身份与单目标删除准备分层

日期：2026-11-03，UTC+8。版本：`0.1.0rc6.dev18`。本地候选，未提交、未推送。

本轮依据 dev17 现有问题确认清单及第九轮审查修复 B1/B2/B3，补充 Q1/D1 的来源和诊断。**离线逻辑已验证；实际六字符类型及其角色仍缺现场证据，不能宣称现场删除已恢复。**

## 一、实际改动

### 1. 完整身份与删除参数分层

- `IdentityEntry` 保留每一项的稳定 ID、可对应名称、类别标记及本次内存数据；它不代表删除许可。
- 完整列表核对不再要求所有类型必须是 `USER / DSH`，也不要求旁观条目的 `sensitive_id / created_at` 合法。未知、缺失、null 或异常类型的旁观项，只要身份能独立完整核验，仍可参与身份列表。
- 所有身份仍须有完整 ID、唯一且与网页全量对应；未知项不能被过滤、按行号猜测或套用 DSH 名称映射。
- 完整身份匹配后，按所选完整 ID 选目标，才验证目标类别与删除参数。已知 DSH 拒绝普通删除；未知目标即使字段齐全也返回 `KEY_TARGET_KIND_UNSUPPORTED`，没有新许可或 POST。
- 当前仅保留原有 `USER` 候选目标路径，不增加未经观察的类型枚举。这是缩小旧检查作用域，不是证明 USER 是官方完整普通类型集合；其来源局限见下文。
- 目标的脱敏标识若与其他项重复，仍拒绝；不再因为两个非目标项仅动作字段重复而拒绝身份读取。
- `ConsoleKeyManager.read_keys()` 改为仅读取身份，用于提交后的独立核实。幸存项动作字段为空或普通类型变为未分类，不再单独造成核实失败。涉及 DSH 显示映射的变化仍拒绝。
- 每次准备重新读取；预检不缓存许可。实际提交后的异常仍是结果未知，不降格为“未提交”，不自动重发，不走网页点击后备。

### 2. 状态提示

- 最近成功保存的费用，记录其账本、期间、快照和原观察时间，仅作为历史显示事实。
- 管理契约失败时显示“最近费用已保存 / 管理准备未通过 / 当前删除资格失效”，避免把管理失败混同成费用保存失败或平台退出登录。
- 仍停止管理，清除当前会话与费用的动作资格，不修改或延长费用观察时间。没有成功费用快照时不显示“费用已保存”。
- 历史事实不跨账本、期间或不同快照复用。用户可以直接重新读取核验，不强制先退出再登录；成功重新读取也不自动重新开启管理。

### 3. 有界诊断与来源

- 诊断 schema 升为 3。新增 `http_row_ordinal` 明示 HTTP 数组一基序号；旧字段 `count` 在字段拒绝事件里继续保留原序号语义，不作为身份键。
- 在内存以完整 ID 关联目标和网页身份。日志仅保留 `is_selected_target`、`dom_identity_matched`、固定类别、字段形态和删除参数是否合法等布尔值。
- 每次最多输出 20 个未知非目标结构项，加当前目标；不记录原始类型字符串、真实名称、完整稳定 ID、掩码 Key、响应、请求头、Cookie 或授权。
- 未知项是否实际属于 Harness，只有已证明的类型/名称映射才能确认；当前诊断不伪造这个结论。原始类别标量仍需单独受控观察。
- 原日志清理与文件大小限制保留；财务处理记录不随诊断清理而删除。

### 4. 保留的业务与保护

`-1` 跳过、空名不管理、零额度触发、正额度有效费用门槛、强制删除不要求达额、全自动无需逐枚审批均不变。全量身份、账户连续性、最后一枚 Key 保护、跨账本目标互斥、旧未决责任及单次提交许可不变。未支持的选中目标失败仍暂停队列，没有静默跳过或反复尝试。

## 二、改动理由与证据来源

B1 的现场直接原因是全表精确类型白名单：第二 HTTP 项为非空六字符类型，不等于 USER/DSH。B2 的非目标空动作字段连带失败已用合成输入重现；该检查被错误放在选择目标之前。B3 是失败后抹去当前资格的同时也抹平了“费用已成功保存”的可见事实，并非账本被清空。

| 关键字段 / 规则 | 依据 | 本轮能与不能证明 |
| --- | --- | --- |
| `tracking_id`、`name` 列表映射 | 2026-10-31 保存的官方前端字段映射；现有网页/HTTP 身份设计 | 要求全 ID 与名称完整对应；不证明所有未来类型的显示映射 |
| DSH 特殊名称及按钮禁用 | 缓存前端明确比较 DSH，展示 Harness / App-managed | 支持已知 DSH 的显示与普通删除限制；不证明类型集合仅有两项 |
| USER | 旧合成夹具及现有候选适配路径；没有字段级真实契约记录 | 不再当作全表合法性标准；尚未补足现场类别证据，不宣传为官方类型定义 |
| 六字符未知类型 | dev17 结构日志与精确错误分支 | 确认不兼容；未知真实值、目标角色及普通管理语义 |
| `sensitive_id` → `redacted_key` | 缓存请求映射；dev16 现场有空字符串失败 | 仅目标参数必须真实且有效，不能制造值；旁观项不必提供 |
| `created_at` 整数秒 | 缓存映射在展示时乘 1000、发送时除 1000；合成边界测试 | 当前适配规则，现场值与未来结构仍需复核 |
| 请求/响应信封与删除效果 | 候选适配、合成传输测试及历史有限真实案例 | 离线通过不代表本版真实提交或失效生效 |

夹具增加字段级 provenance；所有测试名称、身份、日期与 CASE06 均为合成数据，CASE06 不是对现场六字符值的猜测。没有把合成通过当成真实协议证明。

## 四、仍未解决或未验证的事项

1. **六字符类型、目标/非目标归属及 Harness 对应关系仍未补证。** 用户准备通过 Burp 提供 GET 列表的最小脱敏信息。不同会话的新响应只能证明新观察，不能直接当作旧请求原文。
2. **USER 候选目标路径的真实字段来源仍待核对。** 本轮未扩大未知目标权限，也不宣称当前适配已覆盖真实普通 Key 的所有类型。若实际目标为未知类型，仍会明确拒绝，需要依据实际响应与官方行为进一步适配。
3. dev16 空敏感字段究竟属于目标还是旁观项仍未知。分层消除了旁观连带阻断，不会让目标空参数变得可用。
4. dev17 较早登录检查 GuardError、历史长区间业务拒绝与费用归属缺交集继续分别保留，未用当前类型问题包办解释。
5. 本版真实只读准备、单次真实撤销、独立缺席核实及旧凭据调用失效尚未验收。正额度真实消费跨线的周期自动撤销、Excel/WPS 真实导入、长期运行与同机干扰也尚未验收。

下一步先核对 Burp 的列表响应字段与角色；之后保持自动管理停止，用明确普通测试目标完成只读预检。取得只读证据仍不等于真实撤销成功，不擅自安排付费或删除。
